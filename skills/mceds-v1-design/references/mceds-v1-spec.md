# MCEDS v1 — Master Production Specification

Source: *Developing eBooks with AI: Three-Stage Express Workflow*, Appendix A — Made Clear Educational eBook Design System (MCEDS v1). © 2026 Munaisyah Abdullah. Used with permission.

This specification is **frozen**. Use it as a design specification, not as inspiration. Do not reinterpret it, modernise it, replace it with another template, introduce a different colour palette, or create a generic academic-document design. A new eBook produced with it should look as though it belongs to the same publication family as the reference eBook.

The short instruction "Apply MCEDS v1 exactly; do not reinterpret the visual system" is valid only when this specification is available in the same conversation, attachment set or approved project file.

---

## 1. Design principle

The design must feel professional; academic but approachable; highly readable; structured for independent learning; clean rather than decorative; visually consistent; table-friendly; workbook-friendly; suitable for screen and print.

Use white space, colour-coded learning blocks, tables and strong heading hierarchy to organise information.

Avoid: decorative gradients; excessive icons; crowded layouts; dark full-page backgrounds except where specifically authorised; random colour use; rounded app-style cards; excessive shadows; unnecessary illustrations; decorative typography; overly modern dashboard styling.

The result must look like a professionally designed university educational eBook, not a presentation slide deck.

## 2. Page format

| Setting | Value |
| --- | --- |
| Page size | A5 portrait, 148 mm × 210 mm |
| Left margin | 12.5 mm |
| Right margin | 12.5 mm |
| Top content zone | approximately 16 mm |
| Bottom content zone | approximately 14 mm |
| Layout | single-column reading layout (default) |
| Main usable content width | approximately 123 mm |

Maintain generous white space. Do not fill every available area merely because space exists. A page may intentionally contain substantial white space when this improves comprehension or separates learning stages.

## 3. Fixed colour palette

Use ONLY this core palette unless an authorised figure requires additional colours.

| Name | Hex |
| --- | --- |
| Primary deep navy | `#0B2E4E` |
| Section navy | `#102D5B` |
| Teal | `#169FB2` |
| Orange | `#F28C28` |
| Pale teal | `#DDEFF2` |
| Pale peach | `#FCE4D6` |
| Alternating table grey | `#F2F2F2` |
| Body text | `#222222` |
| Secondary text | `#555555` |
| Topic-opening accent blue | `#4F81BD` |
| White | `#FFFFFF` |

Colour meaning must remain consistent throughout the entire eBook. Do not substitute approximate unrelated colours.

## 4. Typography

Use Arial or the closest metrically compatible Arial-family font.

| Element | Font | Size | Colour / notes |
| --- | --- | --- | --- |
| Body text | Arial Regular | 11 pt | `#222222`; mostly justified; line spacing approximately 1.15–1.2; clear paragraph separation; no first-line indentation unless specifically required |
| Table text | Arial Regular | approximately 10 pt | |
| Table header text | Arial Bold | approximately 10 pt | white |
| Normal section / subsection title | Arial Bold | approximately 11–12 pt | navy |
| Topic number on topic-opening page | Arial Bold | approximately 16 pt | white |
| Topic title | Arial Bold | approximately 12–14 pt | white, uppercase |
| Topic-opening motivational statement | Arial Bold Italic | approximately 16 pt | `#4F81BD`, centred |
| Block header | Arial Bold | approximately 11 pt | white, uppercase |
| Footer | Arial Italic | 9 pt | `#555555` |

Use bold selectively for: section labels; learning outcomes; table headers; short subheadings; key terms; instructional emphasis. Do not overuse bold or italics.

## 5. Running page system

Every normal interior page must use the same running-page system.

**Page number** — a small orange rectangular box in the upper-right corner, approximately 10 mm wide × 7 mm high, fill `#F28C28`, page number centred inside in dark text. Do not add a circle, border, shadow or icon.

**Footer** — a thin orange (`#F28C28`) horizontal rule approximately 12.5 mm from the left and right page edges. Below the line, centre the copyright or approved footer text (for example `Copyright©2026 [INSTITUTION]`) in Arial Italic 9 pt `#555555`. Maintain this footer consistently across interior pages.

## 6. Topic opening page template

Every major topic begins on a dedicated topic-opening page.

- At the upper part of the page, one large horizontal navy rectangle (`#0B2E4E`) spanning almost the full content width.
- Inside the block: `TOPIC [NUMBER]` followed by the topic title beneath it — white, bold, uppercase, centred. Do not add icons.
- Below the navy topic panel, leave substantial white space.
- Then a short learner-facing hook or motivational statement: Arial Bold Italic, approximately 16 pt, `#4F81BD`, centred, 2–4 short lines maximum.
- Add a thin horizontal blue line beneath the motivational statement.
- Do not overcrowd topic-opening pages. The page should feel spacious and confident.

Example structure of a hook:

> Unsure how to conduct your study?
> Chapter 3 turns your research
> idea into a clear action plan.

## 7. Main section heading template (split navy-bar motif)

At the top of a new major section:

- create a solid navy rectangular bar occupying approximately the left half of the heading width;
- leave the right half white;
- place the section heading in uppercase navy text on the white area to the right of the bar.

Examples: TOPIC OVERVIEW · LEARNING PATHWAY · KEY TERMS / GLOSSARY · LESSON 1: … · ADDITIONAL EXAMPLES · SUMMARY

The navy rectangle is visual decoration only and does not contain text for this heading type. If the heading requires two lines, increase the heading height naturally. Do not replace this motif with a normal standalone heading.

## 8. Learning block system

Use these block types exactly and consistently. No rounded corners. No shadow.

### A. Teal learning block

Use for: KEY IDEA · KEY CONCEPT · KEY TAKEAWAY · IMPORTANT CONCEPT · ESSENTIAL POINT

- Header: `#169FB2`, white bold uppercase text.
- Body: `#DDEFF2`, dark body text.
- Header and body together form one full-width rectangular learning block.

### B. Orange learning block

Use for: WHY THIS TOPIC MATTERS · EXAMPLE · WEAK-EXAMPLE · SELF-CHECK · FINAL REMINDER · BEFORE FINALISING… · CAUTION or learner-facing warning where appropriate

- Header: `#F28C28`, white bold uppercase text.
- Body: `#FCE4D6`, dark text.

### C. Mini activity block

- Full-width teal title bar `#169FB2` with white bold uppercase text, e.g. `MINI ACTIVITY 1: WHAT IS CHAPTER 3 FOR?`
- Instructions beneath the header on the white page background.
- Then an editable table, checklist or learner-response area.
- Do not enclose all activity content unnecessarily in a coloured box.

### D. Reflection

- Use a major section heading.
- Provide clearly numbered questions.
- Use visible response lines or editable response spaces.
- Keep the page clean and spacious.

## 9. Table design system

Tables are a major visual element and must look consistent throughout the eBook.

**General rules**

- Use real editable tables.
- Use thin black/dark-grey borders. Do not use thick decorative borders.
- Use sufficient cell padding. Align text vertically near the top.
- Do not compress rows excessively.
- Do not shrink text below approximately 9.5–10 pt merely to fit a page.

**Table style A — navy header.** Use for conceptual comparisons; reference information; common mistakes; methodology comparisons; learning outcomes; analytical information. Header fill `#102D5B`, header text white bold. Rows alternate `#FFFFFF` and `#F2F2F2`.

**Table style B — teal header.** Use for activities; learner worksheets; application exercises; selected example tables; action-oriented content. Header fill `#169FB2`, header text white bold. Rows alternate white and `#F2F2F2`.

**Table style C — pale-blue label column.** Where one column functions as a category/question label, fill the label cells with `#DDEFF2` and use bold navy text. Remaining cells white or alternating light grey. Do not over-colour tables.

## 10. Body content layout

Use clear single-column body text. Allowed: paragraphs; short numbered lists; bullet lists; instructional questions; subheadings; diagrams; tables; learning blocks.

- Do not turn ordinary explanatory text into coloured boxes. Reserve colour blocks for information that deserves instructional emphasis.
- Use approximately 6–10 pt visual space between logical content units.
- Keep headings with the first paragraph beneath them. Avoid orphaned headings.
- Do not place only one table row on a new page where avoidable.

## 11. Visuals and diagrams

When a diagram is required:

- use a white background;
- favour navy, teal, orange and blue accents;
- use simple clean arrows and shapes;
- avoid 3D effects unless the authorised original visual requires them;
- use thin borders;
- centre the diagram;
- preserve adequate white space around it.

The visual should teach a relationship, process or comparison. Do not add decorative stock photographs to interior learning pages unless specifically requested. Place the figure caption directly below the figure, centred where appropriate. Keep the figure and caption together.

## 12. Cover design language

If a cover is required, create an original cover using the same visual family; do not reproduce unrelated copyrighted photographs. Use:

- white upper area;
- deep navy lower or curved area;
- teal curved accents;
- restrained gold/orange line accents;
- professional academic imagery related to the subject;
- large serif-style or high-impact title treatment only if consistent with the approved cover direction;
- clear subtitle;
- short learner promise or quotation;
- 3–4 concise benefit statements if appropriate;
- author names near the lower area.

The interior design remains Arial-based even if the cover uses a contrasting title typeface.

## 13. Topic structure

Where the learning content supports it, use this repeated topic architecture:

1. Topic Opening Page
2. Topic Overview
3. Why This Topic Matters
4. Topic Learning Outcomes
5. Learning Pathway
6. Key Terms / Glossary
7. Lesson 1 — explanation · Key Concept · examples · common mistakes · Mini Activity · Self-Check · Key Takeaway where appropriate
8. Lesson 2
9. Lesson 3
10. Additional Examples
11. Quiz
12. Reflection
13. Summary
14. Final Reminder
15. Key Takeaways

Adapt the number of lessons when the content requires it. Do not create empty sections merely to force this pattern.

## 14. Quiz design

- Use normal readable text for multiple-choice questions.
- Use tables where useful for True / False; answer/explanation; application questions; short-answer questions.
- Use navy or teal headers. For application or short-answer tables, the question column may use pale teal with bold navy text.
- Suggested answers must remain clearly distinguishable.
- Do not make quizzes look like colourful games. Maintain the academic workbook style.

## 15. Page density

Target moderate content density. Per page, prefer: 1 substantial table; or 1 diagram + supporting explanation; or 2–3 instructional blocks; or normal prose plus one block.

Do not force content to fill the bottom of every page. Some pages may be intentionally sparse. Readability has priority over maximising page count efficiency.

## 16. Design semantics — never change

| Colour | Meaning |
| --- | --- |
| NAVY | structure, reference, formal academic information |
| TEAL | learning concept, activity, application, key takeaway |
| ORANGE | attention, example, self-check, warning, importance, reminder |
| PALE TEAL | supporting explanation for teal learning blocks |
| PALE PEACH | supporting explanation for orange attention blocks |
| LIGHT GREY | alternating table row only |

Do not change these meanings between topics.

## 17. Editability rule

When producing Microsoft Word:

- body text, headings, page numbers, headers and footers, captions and response spaces must remain editable;
- learning blocks should be native Word tables/text boxes where practical;
- tables must be real Word tables;
- diagrams may remain embedded images when necessary.

Do not flatten an entire page into an image. Create the editable Word master first. Generate the publication PDF from the final Word master only after layout review.

## 18. Content-preservation rule

Design must never shorten academic content. Do not summarise; compress; remove examples; merge activities; delete feedback; simplify tables; omit figures; or reduce explanations merely to make the page look cleaner. Instead, allow content to flow onto additional pages while maintaining the same design language.

## 19. Reproducibility rule

Treat this specification as a DESIGN SYSTEM, not as inspiration. Do not invent alternative layouts when an equivalent template already exists. When the same semantic information appears again, reuse the same visual treatment.

- Every KEY CONCEPT must look like every other KEY CONCEPT.
- Every SELF-CHECK must use the same orange/peach structure.
- Every MINI ACTIVITY must use the same teal activity-header treatment.
- Every table of the same function must use the same header and zebra-row rules.
- Every topic opener must use the same placement logic.
- Every normal page must use the same page-number and footer system.

Consistency is more important than novelty.

## 20. Quality control before delivery

Before finalising the eBook, inspect every page. Confirm:

- [ ] A5 page size is correct
- [ ] margins are consistent
- [ ] page numbers use the orange upper-right box
- [ ] footer line and copyright are aligned
- [ ] topic opening pages follow the frozen template
- [ ] section-heading bars are consistent
- [ ] colour meanings are consistent
- [ ] body text is approximately 11 pt
- [ ] tables remain readable
- [ ] coloured blocks are not overused
- [ ] no block is split awkwardly across pages
- [ ] no heading is stranded
- [ ] no table is clipped
- [ ] no image is stretched
- [ ] no text extends beyond margins
- [ ] no unexpected font appears
- [ ] no random colours appear
- [ ] adequate white space remains
- [ ] the final book looks like one coherent publication

If a design decision is not explicitly defined, select the option that most closely preserves the restrained university eBook appearance described above.

DO NOT replace this system with a generic Word template. DO NOT redesign it. DO NOT make it more colourful. DO NOT make it more minimal. DO NOT make it look like PowerPoint. REPRODUCE THIS DESIGN SYSTEM CONSISTENTLY.

## Inputs (master design prompt)

- eBook title
- Subtitle
- Authors
- Institution / copyright
- Target learners
- Approved learning outcomes (exact wording)
- Topics (list)
- Approved content/source files

Required output: (1) fully editable Microsoft Word master; (2) publication-ready PDF derived from the Word master.

Final instruction: use the supplied content exactly. Apply the frozen design system to the complete eBook. The final product must visually belong to the same design family across every topic and every page. Do not provide only a sample page. Produce and verify the complete eBook.
