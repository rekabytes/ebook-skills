# MCEDS v1 Design System

Source: *Developing eBooks with AI: Three-Stage Express Workflow*, Appendix A. © 2026 Munaisyah Abdullah, used with permission. Every rule here comes from that eBook; do not add design rules from elsewhere.

MCEDS v1 is the **controlling production design system** for eBooks made with this workflow. It is a specification, not inspiration.

## Before you design

1. Read [the full specification](references/mceds-v1-spec.md). The short instruction "Apply MCEDS v1 exactly" is valid only when that specification is available in the same conversation, attachment set or project.
2. Read the approved course-specific Visual Style Guide if one exists. It may record cover/identity, learning emphasis, asset needs, accessibility, printing and **explicitly authorised** exceptions. It must not redefine MCEDS v1. Where the guide is silent or conflicts without explicit authorisation, MCEDS v1 controls.
3. Design only content that has been approved (Gate A **KEEP CONTENT** or frozen KEEP DESIGN topics). Never design unapproved drafts.

## Non-negotiable rules

- **Do not reinterpret, modernise, simplify, recolour or substitute** another visual style. A learning-design emphasis (Clean Academic, Colourful Learning Guide, Visual-First Technical, Activity-Centred Workbook, Hybrid) may change how much explanation, diagrams or practice a topic has, but never the page format, palette, typography, topic opener, section-heading motif, block semantics, table system, page-number treatment or footer.
- **Colour semantics never change.** NAVY = structure, reference, formal academic information. TEAL = learning concept, activity, application, key takeaway. ORANGE = attention, example, self-check, warning, importance, reminder. PALE TEAL = body of teal blocks. PALE PEACH = body of orange blocks. LIGHT GREY = alternating table row only.
- **Reproducibility.** If a semantic element already has an MCEDS treatment, reuse it exactly. Every KEY CONCEPT matches every other KEY CONCEPT; every SELF-CHECK uses the same orange/peach design; every MINI ACTIVITY the same teal design; tables of the same function the same style; every topic opener the same placement; every normal page the same page-number and footer. Consistency is more important than novelty.
- **Content overrides page count.** Never reduce, summarise, merge or remove approved content to fit the layout. Add pages instead.
- **Editability.** Produce a fully editable Word (.docx) master. Body text, headings, real Word tables, worksheets, response areas, learning blocks, captions, page numbers, headers and footers stay editable. Diagrams may be embedded images when inherently image-based. Never flatten pages into images. Generate the PDF only from the final checked Word master.

## Quick reference

| Item | Value |
| --- | --- |
| Page | A5 portrait 148 × 210 mm; margins L/R 12.5 mm, top ≈16 mm, bottom ≈14 mm; single column ≈123 mm |
| Fonts | Arial. Body 11 pt `#222222`, justified, 1.15–1.2 spacing. Tables ≈10 pt. Section titles bold 11–12 pt navy. Footer italic 9 pt `#555555` |
| Palette | navy `#0B2E4E`, section navy `#102D5B`, teal `#169FB2`, orange `#F28C28`, pale teal `#DDEFF2`, pale peach `#FCE4D6`, grey `#F2F2F2`, body `#222222`, secondary `#555555`, accent blue `#4F81BD`, white |
| Page number | orange `#F28C28` box ≈10 × 7 mm, upper right, dark centred number, no border/shadow/icon |
| Footer | thin orange rule, centred copyright text beneath, Arial Italic 9 pt `#555555` |
| Topic opener | navy `#0B2E4E` panel, white bold uppercase centred `TOPIC n` + title; white space; 2–4 line hook in `#4F81BD` bold italic ≈16 pt centred; thin blue line under it |
| Major section heading | solid navy bar on the left half, uppercase navy heading text on the white right half |
| Teal block | KEY IDEA / KEY CONCEPT / KEY TAKEAWAY / IMPORTANT CONCEPT / ESSENTIAL POINT — teal header, pale-teal body |
| Orange block | WHY THIS TOPIC MATTERS / EXAMPLE / WEAK-EXAMPLE / SELF-CHECK / FINAL REMINDER / BEFORE FINALISING… / CAUTION — orange header, pale-peach body |
| Mini activity | teal title bar, instructions on white, then editable table/checklist/response area |
| Table A (navy header `#102D5B`) | concepts, reference, common mistakes, comparisons, learning outcomes |
| Table B (teal header `#169FB2`) | activities, worksheets, application, action-oriented content |
| Table C | pale-teal `#DDEFF2` label column with bold navy text |
| All tables | real tables, thin dark borders, white/`#F2F2F2` zebra rows, never below ≈9.5–10 pt |

No rounded corners, no shadows, no gradients, no decorative icons or stock photos on interior pages.

## How to apply it to a topic

1. Map each piece of approved content to one MCEDS treatment: normal prose, learning block, numbered procedure, list, table (A/B/C), formula panel, figure panel or worksheet/response area. Do not turn ordinary explanation into coloured boxes.
2. Use the topic architecture in section 13 of the spec only where the content supports it. Do not create empty sections to force the pattern.
3. Place every figure, table, formula and image where it supports learning. If the final image is unavailable, keep a designed placeholder in the real layout showing size, position, caption, source/permission status and alt-text requirement.
4. Keep moderate density: per page, about 1 substantial table, or 1 diagram with explanation, or 2–3 blocks, or prose plus one block.
5. Render the complete output and inspect every page with the checklist in section 20 of the spec.
6. Record any deviation from MCEDS v1 and get explicit authorisation before approval.

If a design decision is not explicitly defined, choose the option that most closely preserves the restrained university eBook appearance. Do not make it more colourful, more minimal, or like PowerPoint.
