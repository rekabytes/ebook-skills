# Markers and Decisions

From *Developing eBooks with AI: Three-Stage Express Workflow* by Munaisyah Abdullah.

## Visible gap markers

Use these exact markers in drafts for non-critical gaps instead of asking questions or guessing.

| Marker | Use when |
| --- | --- |
| `[CONFIRM SOURCE AUTHORITY]` | It is unclear whether a source is authorised |
| `[CONFIRM DELIVERY FEATURE]` | A delivery feature (format, platform, interactivity) is uncertain |
| `[ASSET TO BE CREATED]` | A visual or asset is not available yet |
| `[LECTURER INPUT REQUIRED]` | Content needs the lecturer's own input or decision |
| `[SOURCE EXTENSION REQUIRED]` | The authorised sources do not yet cover what the topic needs |
| `[FORMULA VERIFICATION REQUIRED]` | A formula, symbol, unit or step is uncertain |
| `[FIGURE/TABLE SOURCE REQUIRED]` | A figure or table needs a source |
| `[IMAGE PLACEHOLDER]` | An image location is reserved for a later asset |
| `[COPYRIGHT/PERMISSION CHECK]` | Ownership, licence or permission needs checking |

Markers are approved content once a topic is frozen. Keep them through assembly until resolved, and list them in registers and release records.

## Decisions by stage

| Stage / gate | Allowed decisions |
| --- | --- |
| Stage 1 | KEEP (approve setup and Blueprint) · REVISE (modify named elements) · HOLD (an essential academic or source blocker remains) |
| Stage 2 Gate A | KEEP CONTENT (approve manuscript, proceed to Gate B) · REVISE CONTENT (revise named content) · HOLD (essential academic, source, formula or permission evidence missing) |
| Stage 2 Gate B | KEEP DESIGN (freeze content and design, start next topic) · REVISE DESIGN (revise named visual, layout or delivery elements without altering content) · REVISE CONTENT (return to Gate A) · HOLD (an essential asset, permission or delivery requirement blocks approval) |
| Stage 2 → 3 | PROCEED TO ASSEMBLY (permission gate only; confirm readiness and wait for Prompt 3) |
| Stage 3 | Exactly one: READY FOR HUMAN TESTING · REVISION REQUIRED · RELEASE READY (only when required human testing/approval has actually been completed and documented) |

## Defect levels (Stage 3)

| Level | Meaning | Release effect |
| --- | --- | --- |
| CRITICAL | Academic, legal, safety or functionality failure | Release blocked |
| MAJOR | Material learning or usability defect | Correction and retest required |
| MINOR | Improvement that does not prevent intended use | Correct now or schedule |
| KNOWN LIMITATION | Unresolved constraint accepted and disclosed | Release only with approval |
