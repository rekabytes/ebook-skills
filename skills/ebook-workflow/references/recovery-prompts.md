# Recovery Prompts — When AI Goes Off Track

From *Developing eBooks with AI: Three-Stage Express Workflow* by Munaisyah Abdullah.

When you notice one of these problems in your own work (or the user points it out), apply the matching correction immediately.

## AI asks too many questions

Apply the Question-Control Rule. Use the supplied files first. Ask no more than three consolidated questions, only for genuine blockers. Convert non-critical gaps into labelled recommendations and continue.

## AI starts drafting the whole book

Stop. Return to the approved stage. Develop only the current topic. List any content created beyond the authorised boundary and exclude it from the working version.

## AI changes the learning outcome

Restore the exact approved learning outcome without rewriting it. Recheck the Blueprint and current topic against this exact wording.

> Approved outcome: [PASTE EXACT OUTCOME]

## The writing sounds generic

Map every substantive paragraph to an authorised source and a learner need. Mark unsupported or unnecessary text for removal. Add only source-grounded explanation, examples or demonstrations.

## Visuals are decorative

Audit every visual. State the learning problem, what the learner must see, why prose alone is insufficient, where the visual appears, and its source, permission and alternative-text requirements. Remove visuals without a defensible learning purpose.

## AI claims testing passed

Withdraw unsupported PASS claims. Separate AI inspection from actual human or technical testing. Produce a test plan with procedure, expected result, evidence, tester and environment.
